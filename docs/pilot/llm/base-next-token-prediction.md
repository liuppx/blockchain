## 核心陈述

自回归生成式语言模型会根据当前上下文计算下一个词元的分数或概率分布,按解码策略选出词元并追加到上下文,
再继续生成,直到停止条件满足。推理过程可逐步生成,但模型通常会并行计算当前这一步各候选词元的分数。

## 正文

### 一步在做什么

输入是一串词元。在当前生成位置,模型为词表中的候选词元计算分数(logits),经 softmax 等处理后可得到
下一个词元的概率分布。例如前文是
"今天天气很",下一个是"好"的概率可能很高,"冷""热"其次,"桌子"几乎为零。
选出一个词元(怎么选见"采样与温度"),拼到输入末尾,再计算下一步。遇到表示结束的特殊词元,或达到长度上限,就停下。

### 它是怎么学会的

**自回归预训练**:在文本序列中,用前文预测后续词元,根据预测误差调整参数。训练目标会鼓励模型学到
文本中的语法、事实关联和常见模式,但这不保证模型掌握的内容都正确,也不能据此断言模型的内部推理过程。
之后一些模型还会经过**指令微调**和**基于人类反馈的训练**,
让它学会按用户的要求回答,而不只是续写文本。

### 对开发者意味着什么

1. **模型给出的是"可能的下一个词元",不是"查到的事实"。** 流畅不等于正确,这是幻觉的根源之一。
2. **自回归解码通常按步骤生成输出。** 较长输出通常增加生成时间和计算量;输入、输出的价格以及端到端延迟构成取决于服务、模型和请求路径。
3. **前面生成的内容会影响后续步骤。** 已生成词元成为后续上下文的一部分。要求展示中间步骤在部分模型和任务上可能改善表现,但效果依赖任务与提示,不能代替结果核验。

## 自己验证

许多模型接口能返回每个输出词元的对数概率(常见参数名如 `logprobs`,以你所用接口的文档为准)。
请求一个很短的续写并打开该选项,观察:每个位置都有若干候选词元及其概率,被选中的不一定是概率最高的那个
(取决于采样设置)。

也可以用本地的小模型做同样的观察(依赖 `pip install transformers torch`,首次运行会下载约 500 MB 的 GPT-2 模型):

```python
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch
tok = AutoTokenizer.from_pretrained("gpt2"); model = AutoModelForCausalLM.from_pretrained("gpt2")
ids = tok("The capital of France is", return_tensors="pt").input_ids
probs = torch.softmax(model(ids).logits[0, -1], dim=-1)
top = torch.topk(probs, 5)
for p, i in zip(top.values, top.indices):
    print(f"{tok.decode(i)!r:>12}  {p:.3f}")
```

预期:输出前 5 个候选词元及其概率。由于这里只显示词表中的 5 项,它们的概率之和通常小于 1,余下概率分布在未显示的候选项中。

## 适用范围与局限

- 适用:GPT 类的自回归语言模型,即当今主流的对话与生成模型。
- 不适用:扩散式文本生成等其他生成方式(目前不是主流)。
- 容易过时的部分:"输出比输入贵"之类的计费关系因厂商而异。

## 核验要点(给人类审查者)

1. 确认自回归预训练的说明没有暗示所有生成模型都使用相同训练目标。
2. 确认文中将思维链效果限定在部分模型与任务,没有写成普遍保证。
3. GPT-2 示例代码**起草时没有运行**(需下载约 500 MB 模型),请实际运行一遍,确认库接口没有变化、输出与描述一致。
4. 确认费用与延迟表述不把某家服务的价格或性能规律推广至其他服务。
