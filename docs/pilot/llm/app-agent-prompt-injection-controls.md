## 核心陈述

当智能体读取网页、邮件、文件或工具返回内容时,这些内容可能携带试图改变智能体行为的恶意指令。应用不能仅靠系统提示要求模型“忽略攻击”来保证安全。应将外部内容视为不可信数据,限制它可影响的决策与数据流,并在工具和执行环境中实施权限控制、输入校验与高影响操作确认。分层控制可以降低风险,不能证明提示注入已被彻底解决。

## 正文

### 风险从数据流进入操作

提示注入是指不可信输入包含试图覆盖系统行为的指令。攻击内容可能来自用户输入,也可能隐藏在被检索或读取的网页、邮件、文档和工具结果中。间接提示注入的危险在于,模型可能把这些内容当成指令,继而借助已有工具权限读取或外传数据、修改记录或执行用户未要求的操作。

应用应检查完整数据流,从不可信来源进入模型上下文开始,经过模型生成的结构化结果,直到最终工具副作用。提示词中的信任声明只能表达意图,不能替代对输出和工具权限的验证。

### 在架构和权限层降低影响

1. 将外部文本作为数据传递,避免拼接进具有更高指令优先级的开发者消息。为不同来源保留清晰边界与来源信息。
2. 让模型输出受限结构,例如固定字段、枚举值和严格 schema。应用校验类型、取值范围、资源归属和业务不变量,再将有效字段映射到工具参数。
3. 为每个工具配置完成任务所需的最小权限。读取、写入和外发能力应按任务拆分,并限制目标资源、数据范围和速率。
4. 在执行前由策略层检查调用是否符合用户意图和当前授权。模型生成的工具调用仅是待评估请求,不代表用户授权。
5. 对不可逆、高影响或向外披露数据的操作要求用户确认,并在界面中展示对象、数据范围、目标和预期副作用。确认信息应来自实际待执行操作,不能只显示模型的自然语言摘要。
6. 使用沙箱、隔离凭据和网络访问控制限制工具执行环境。日志应能关联输入来源、模型输出、策略判定、用户确认与实际副作用,并避免记录不必要的敏感内容。

### 评测与监控

- 建立包含直接注入和间接注入的测试集,覆盖网页、邮件、附件、检索片段和工具返回内容。
- 为每个场景预先写明允许的最终状态、禁止的副作用和授权边界。评分时分别统计任务完成、违规调用、未授权数据访问与数据外发。
- 在工具被允许、拒绝和要求确认的边界上测试,同时检查绕过尝试、错误恢复和重复执行。
- 记录模型、提示、工具 schema、权限策略和评测集版本。对策略或模型更新运行相同回归任务,人工复核自动评分器无法确定的案例。
- 生产环境监测拒绝、拦截、确认取消和实际副作用。攻击成功率取决于模型、工具、攻击者能力与环境,单次测试结果不能解释为通用安全保证。

### 简化的执行边界示例

下面的应用逻辑只允许读取一个已授权记录。模型即使从不可信文档中生成其他记录编号,工具边界仍会拒绝该请求。

```python
def read_record(requested_id, authorized_ids, records):
    if requested_id not in authorized_ids:
        raise PermissionError("record is outside the user's authorized scope")
    return records[requested_id]

authorized_ids = {"case-17"}
records = {"case-17": "approved summary", "case-99": "private data"}

assert read_record("case-17", authorized_ids, records) == "approved summary"
try:
    read_record("case-99", authorized_ids, records)
except PermissionError:
    print("blocked")
```

预期输出为 `blocked`。这个例子只说明服务端资源授权检查的作用,不能代表一个完整的智能体安全方案。

## 对开发者意味着什么

1. 绘制从外部内容到模型、策略层、工具和最终数据副作用的数据流,标记信任边界。
2. 把身份认证、资源授权和业务不变量放在应用或工具服务端执行,不依赖模型自行遵守提示。
3. 将模型可调用的工具设计为范围窄、参数受限、权限最小的操作。
4. 按影响级别设计确认与审计,确保确认绑定具体操作,并能在执行后核对真实副作用。
5. 用攻击测试和正常任务回归同时衡量防护效果与可用性,发现失败后收紧权限或数据流并重跑测试。

## 适用范围与局限

- 适用:读取不可信外部内容且可调用工具、访问敏感数据或改变外部状态的智能体应用。
- 不适用:把防护措施列表当作一次性认证,或将提示词、分类器、确认按钮中的任意单项视作安全证明。
- 需按应用决定:工具权限粒度、确认阈值、日志保留、沙箱边界和攻击测试覆盖率。
