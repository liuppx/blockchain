## 核心陈述

模型每一步给出的是下一个词元的概率分布,**采样**决定从中选哪一个。**温度**(temperature)调整分布的尖锐程度:
温度低,概率更集中在高分词元上;温度高,概率分布更平。温度会改变采样分布,但不能单独保证答案正确或跨请求可复现。

## 正文

### 温度怎么起作用

模型先为每个词元算出一个分数(logit),再用 softmax 转成概率。温度 T 的做法是**先把分数除以 T 再做 softmax**:

- T < 1:分数差距被放大,概率集中到少数词元上;
- T = 1:保持模型原本的分布;
- T > 1:分数差距被缩小,低概率的词元也有机会被选中;
- T 趋近 0:若最高分唯一,softmax 后的概率趋向集中在最高分词元上,接近**贪心解码**(greedy decoding)。公式要求 T > 0;接口里的 `temperature=0` 通常是另行定义的特殊行为,需查接口文档。

### 另外两个常见参数

- **top-k**:只在概率最高的 k 个词元里选;
- **top-p**(核采样,nucleus sampling):按概率从高到低累加,保留累计概率首次达到 p 的最小候选集合,再在集合内重新归一化采样。

两者都会缩小参与采样的候选集合,并在保留集合内重新归一化概率。它们改变输出分布,但不能保证内容正确或更连贯,效果取决于模型分布与任务。

### 对开发者意味着什么

1. **希望减少采样带来的变化,可以尝试较低温度;希望探索更多表达,可以尝试较高温度。** 低温不保证分类正确,也不保证生成的 JSON 符合格式要求;需要严格格式时,使用接口提供的结构化输出约束并验证结果。
2. **低温或 `temperature=0` 都不单独保证跨请求完全可复现。** 若接口提供 `seed` 等控制项,按文档固定种子、提示、模型版本和其他参数,并记录服务端返回的版本标识。需要保留确切结果时,仍应保存响应。
3. 不同接口和模型的温度取值范围、默认值、是否支持该参数及其效果可能不同,要以所用模型接口的文档为准。

## 自己验证

不需要调用任何模型,用标准库就能看到温度对分布的影响:

```python
import math

def softmax_t(logits, t):
    m = max(x / t for x in logits)
    e = [math.exp(x / t - m) for x in logits]
    s = sum(e)
    return [x / s for x in e]

logits = {"好": 4.0, "冷": 3.0, "热": 2.5, "桌子": -1.0}
for t in (0.2, 1.0, 2.0):
    p = softmax_t(list(logits.values()), t)
    print(f"T={t}: " + "  ".join(f"{k}={v:.3f}" for k, v in zip(logits, p)))
```

预期:T=0.2 时"好"的概率接近 1;T=1.0 时"好"约 0.6,"冷""热"也有一定概率;T=2.0 时分布明显变平,
"桌子"的概率也不再是零。

再用真实模型对比:同一个提示在低温度和高温度下各请求 5 次,比较输出的差异。
