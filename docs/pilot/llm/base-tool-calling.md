## 核心陈述

在常见的工具调用流程中,模型根据对话与工具说明生成一个结构化的调用请求。**应用负责验证请求、执行获准的工具,
再把结果交回模型**;模型输出调用请求本身不等于工具已经执行。

## 正文

### 一次调用如何完成

1. 应用向模型提供对话内容和当前可用工具的名称、用途与参数结构。
2. 模型可以返回普通文本,也可以请求调用一个工具。工具选择与参数由模型生成,因此可能缺失、格式错误或不适合当前用户。
3. 应用检查工具是否在允许列表中,验证参数、用户权限和业务条件,然后才执行对应程序。
4. 应用把工具结果作为后续输入交给模型。模型可以根据结果继续请求工具,也可以生成面向用户的回复。

模型提出调用请求与应用执行工具是两个不同的动作。工具定义为只读操作时,执行仍可能暴露不该访问的数据;
会修改状态的工具还需考虑确认、幂等、重试与审计。

### 一个本地示意

下面的 Python 示例模拟应用收到工具请求后的处理。它只允许查询当前用户自己的订单,不连接模型或真实服务。

```python
ORDERS = {
    "A-17": {"owner": "user-1", "status": "已发货"},
    "B-24": {"owner": "user-2", "status": "处理中"},
}

def execute_tool(user_id, call):
    if call.get("name") != "lookup_order":
        raise ValueError("工具未获准")

    arguments = call.get("arguments")
    if not isinstance(arguments, dict) or set(arguments) != {"order_id"}:
        raise ValueError("参数格式不正确")

    order = ORDERS.get(arguments["order_id"])
    if order is None or order["owner"] != user_id:
        raise PermissionError("订单不存在或当前用户无权查询")

    return {"status": order["status"]}

request = {
    "name": "lookup_order",
    "arguments": {"order_id": "A-17"},
}
assert execute_tool("user-1", request) == {"status": "已发货"}

try:
    execute_tool("user-1", {"name": "lookup_order", "arguments": {"order_id": "B-24"}})
except PermissionError:
    print("已拒绝查询其他用户的订单")
```

这个例子只演示本地应用检查,不代表模型调用格式标准。真实接口的请求字段、工具循环和返回格式须按所用 API 文档实现。

## 对开发者意味着什么

1. **把模型输出视为待验证的数据。** 限定工具允许列表,校验参数类型、必填字段、长度和业务取值。
2. **在执行处实施权限检查。** 不依赖模型自行判断用户能否访问某项数据。
3. **将工具结果作为外部输入处理。** 内容可能包含错误或不可信文本,不能因此提升为系统指令。
4. **区分只读和有副作用的工具。** 修改、发送、付款或删除操作应具有适当的用户确认、幂等和审计机制。
5. **限制工具循环。** 为调用次数、执行时间和资源消耗设定边界,并处理工具失败与超时。

## 自己验证

将代码保存为 `tool_call.py` 并运行 `python3 tool_call.py`。

预期输出:

```text
已拒绝查询其他用户的订单
```

再把工具名改为未允许的名称、删除 `order_id` 参数或加入额外参数,确认调用被拒绝。把 `user_id` 换成订单所有者以外的用户,
确认应用不会泄露订单状态。

## 适用范围与局限

- 适用:模型通过结构化请求调用搜索、数据库、计算或其他应用工具的系统。
- 不适用:模型本身直接执行外部程序的表述;实际执行发生在集成模型的应用或服务中。
- 容易变化的部分:工具调用接口格式、并行调用、异步工具、审批机制和模型的工具选择能力。

## 核验要点(给人类审查者)

1. 核对工具调用 API 的实际流程是否仍为模型提出请求、应用执行并回传结果,并注意不同接口的命名差异。
2. 对照 ReAct 论文原文,确认表述没有把论文方法等同于所有生产工具调用协议。
3. 检查代码是否覆盖未授权工具、参数错误和跨用户访问,且没有把模型输出当成授权依据。
4. 核对外部工具结果作为不可信输入处理的安全建议是否完整。
