## 摘要 / Abstract

大模型正在成为人类知识生产的主要参与者。它写出的每一段文字，都以同样的权威姿态出现在搜索结果、报告和对话里，却不带来源、不带依据、不带任何人对它的担保。人类无法回答三个基本问题：**这是谁写的？它依据什么？谁为它负责？**

知行图（KnowDoGraph）解决的就是这三个问题。

它把"人类和大模型写下的每一条知识"变成**结构化的知识单元**：每个单元只讲一件事，有版本、有来源、有引用、有核验记录。任何人拿到一条结论，都能沿着链追溯到：谁在哪个高度写下它、依据了哪些更早的结论（以及那些结论的依据）、谁核验过它、核验人是否具备资格、后来有没有被新的证据推翻。**可解释不是靠模型自觉标注，而是靠协议结构保证。**

这条链上有两类事实：**知识本身**（内容、版本、来源、引用、核验）与**关于这些事实的共识**（谁在什么时候确认了什么，最终性由谁担保）。前者在链上以哈希承诺，正文存在别处；后者在链上原样记录，任何人可独立重算。**可信度不是链声称的，是算出来的**：一条知识有多可靠，等于它自身有多少位合格核验人认可，并且它所依据的每一条地基同样可靠。

代币 $COG 是这套信任机制的**经济表达，而不是它的前提**。它锚定"知识量"——当被核验、被引用的知识变多时增发，当知识退场、无人使用时销毁；维护这份公共信任的成本由它计价，贡献者与核验者从它获得回报，作恶在它的规则下不划算。

**本白皮书按"已实现 / 设计中 / 未来方向"三层标注每一条主张**，不把愿景写成现状。

## 1. 背景与问题

### 1.1 大模型正在替人类写作

过去检索一个结论，人看到的是作者、机构、出版时间与引用。今天的大模型输出同样权威的段落，但：

- **没有来源**：模型把训练语料里的片段与自己的推断混在一起，无法区分；
- **没有依据**：结论与理由分离，读者只能选择相信或不相信；
- **没有担保**：没有人为一段话负责，因为它没有作者，只有概率分布。

这造成一个具体的困境：**内容越来越多，可信度越来越无从判断**。当人类与大模型共同写作时，"这段话能不能被信任"不再是一个可以靠作者声誉解决的问题——因为很多内容根本没有作者。

### 1.2 现有的两种答案都不够

| 方案 | 做到什么 | 缺什么 |
|---|---|---|
| 中心化平台（维基、知乎、arXiv） | 有作者、有审稿、有版本 | 审稿过程不可见、不可验证；平台可改写历史；不能跨平台复用 |
| 区块链 | 记录不可篡改 | 记录的是资金流动；内容要么不上链，要么上链但没人能读懂 |

前者不**可验证**，后者记录的东西与人类真实的价值创造脱节。

### 1.3 我们要解决的问题

> 如何让"人类和大模型写下的每一条知识"都**可被人类解释**：来源可查、依据可见、担保可核、推翻可追？
>
> 这个问题一旦解决，"知识"才有资格成为公共基础设施——像代码一样可被复用、被审计、被继承。

## 2. 核心理念：可解释的知识

### 2.1 一句话

**把知识从"一段话"变成"一条带担保的断言"。**

一条断言必须能回答：谁写的（人或模型哪个版本）、依据什么（引用了哪些更早的断言）、谁担保过（核验人及其资格）、后来怎样（是否被修订、取代或推翻）。

### 2.2 为什么是图，不是链

认知有层级（基础原理 → 解释 → 场景 → 应用）、有依赖（一条结论站在另一条之上）、有争议（两个互不相容的结论并存）、有继承（一条旧结论被新的整体取代）。用线性账本表达不了这些，而**依赖关系正是可信度的传导路径**：一条知识不可能比它的地基更可靠。

### 2.3 三条不可让渡的原则

| # | 原则 | 含义 |
|---|---|---|
| **P1** | **可解释优先于自动化** | 宁可让人读得懂、走得慢，也不要用不可读的中间表示换取便利。知识的价值在于人能理解它、能据此行动 |
| **P2** | **不引入外部权威** | 不假设某个机构、某个专家、某份榜单天然正确。信任只能来自系统内可验证的记录 |
| **P3** | **诚实的不确定性被保留** | 有争议的问题不强行裁决，让竞争性结论并存，由证据与使用随时间分出高下 |

### 2.4 与"认知地形图"的关系

地形隐喻（峰、高原、山脊、山谷、断层）是对**这张图的读法**，不是图本身。它将在 §9 展开；当前阶段的实现是结构化的知识单元与引用关系（§3），地形是它的可视化投影。

## 3. 知识单元模型

### 3.1 一条知识 = 一个知识单元

参照维基百科词条太粗（混合多个要点，难以精确引用）、知识图谱三元组太细（人读不懂），采用**原子卡片**的粒度：一条单元只讲一件事，且**不需要先读别的单元也能读懂**（可以引用其他单元来深入）。

### 3.2 结构

```
知识单元（固定编号）
 ├─ 层级:基础 / 解释 / 场景 / 应用
 ├─ 版本 v1, v2, v3 …（每次修改一个新版本，旧版本永久保留）
 │    ├─ 语言表达:zh / en / …（同一版本的不同语言，算同一条）
 │    │    ├─ 核心陈述（一两句话）
 │    │    └─ 正文（展开说明、例子、推导）
 │    ├─ 引用:[(单元编号, 引用时的版本号, 类型), …]
 │    ├─ 来源:人工撰写 / 模型生成(记模型名与版本) / 模型生成且人工修改过
 │    └─ 贡献者:作者、修订者、翻译者、核验者（各自签名）
 └─ 生命周期状态:活跃 / 休眠 / 竞争 / 已取代（由链上关系派生）
```

**链上存**：单元编号、层级、版本序列、每个语言正文的 SHA-256、引用、来源标记、签名、核验记录、成员关系。
**正文存链下**：链上只有哈希；正文在内容寻址的正文仓库，浏览器取回后**重新计算哈希**并与链上比对，一致才显示。

### 3.3 引用分两类

起草知识时立刻遇到的问题：「渐进超负荷」与「超量恢复」互相提到对方。若引用一律视为依赖，就会成环，可信度无法传导。

| 类型 | 含义 | 传递可信度 | 可否成环 |
|---|---|---|---|
| **依据** | 本单元建立在被引用单元之上；它若被证伪，本单元也站不住 | 是 | 否 |
| **参见** | 两者相关、可互相补充，一方出错不影响另一方 | 否 | 可以 |
| **取代** | 本单元取代它（旧单元作废，历史与署名保留） | 否（不继承） | 不可成环 |

**取代**是"挑战"的表达方式（§5.2）。

### 3.4 跨语言：同一份正文只能属于一个单元

翻译算"同一条"，不是新知识。因此同一份正文（哈希相同）不能被当作新单元重复提交——否则翻译者可以抢走原作者的署名。要补充另一种语言，应发布为**同一单元的新版本**。

### 3.5 领域

起步两个领域，各自服务不同的人群：

| 领域 | 面向 | 起步单元数 |
|---|---|---|
| **大模型应用开发** | 用 AI、但想真正理解 AI 的开发者 | 约 100 |
| **运动健身** | 久坐、时间少、想保持健康的现代成年人 | 约 50 |

领域只是命名空间；两个领域共用同一套机制。

## 4. 可信度：算出来的，不是声称的

### 4.1 自身可信度

```
自身可信度 = 基础值 + 步长 × 净通过人数        （上限 0.9）
基础值：模型生成且无人核验 0.1；已有人核验通过 0.2
净通过人数 = 计入的"通过"数 − 计入的"需修改"数（下限 0）
```

规则细节：

- 只有**过见习期**的成员，其核验才计入（见习期是防止批量小号刷分的准入门槛）；
- 发布者**不能核验自己发布的版本**；
- 同一核验人对同一版本以**最新结论**为准；
- 核验只对**当时的版本**有效；内容改了就要重新核验；
- 每位"需修改"抵消一位"通过"——多数人认为有错时，可信度不应上升。

### 4.2 有效可信度：地基约束

```
有效可信度 = min(自身可信度, 所依据的每个单元的有效可信度)
```

**一条知识不可能比它的地基更可信。** 被取代的地基不再传递可信度（依据一个已作废的单元，上层同样不可信）。

### 4.3 这套机制为什么重要

- 可信度**自下而上生长**，任何一处薄弱都会在依赖它的地方显现；
- 工具能指出每个单元"被谁卡住"，以及**核验哪个单元能抬高最多下游单元**——引导核验工作先打地基；
- 基础单元被修订或取代时，所有依据它的单元的有效可信度随之下降。

### 4.4 质量如何收敛

收敛机制与四轮仿真推演（见 [`design/knowledge-lifecycle-economy.md`](design/knowledge-lifecycle-economy.md) 与 `sim/`）的核心结论是：**安全建立在"作恶不划算"之上**。

| 机制 | 内容 |
|---|---|
| 挑战有奖 | 任何人可挑战任何单元；成立则挑战者获得被罚没的押金，不成立则挑战者押金被罚没 |
| 悬赏与影响力挂钩 | 越重要的知识越多人去查，错误在要紧处最快被发现 |
| 内部信誉 | 人人从零开始，信誉只来自系统内记录，按领域计算，随时间衰减 |
| 责任机制 | 作恶重罚；失职（放过当时就能查出的错误）按程度罚；**诚实的错不罚**（原单元标"已取代"，保留历史地位） |
| 追溯奖励 | 少数派后来被证实（地心说 → 日心说），越早、越在少数时支持，奖励越高 |
| 邀请担保 | 新成员须由过了见习期的老成员担保；被担保人**作恶**被查实，担保人连带受罚（失职与诚实犯错不牵连） |

**仿真的最重要结论**：经济机制负责让作恶不划算，但**挡不住大规模作恶**。防线是准入（邀请担保、见习期）。这决定了主网的开放程度必须与社区把关能力匹配。

## 5. 共识与挑战

### 5.1 两类事实，两种共识

| 事实 | 怎么达成一致 |
|---|---|
| **知识内容**（版本、来源、引用、核验） | BFT 共识：谁在什么高度做了什么，由 2/3 投票权的证书担保 |
| **知识的可信度** | 不是共识结论，是**派生值**：任何节点从链上事实独立重算，结果必然相同 |

这与"共识声明一个事实"不同：可信度是**函数**，不是**记录**。因此不需要为它单独做共识，也不存在"共识说它可信"的争议空间。

### 5.2 挑战：提交竞争单元，而不是举报

举报会进入裁决，可能被多数压制；竞争单元与原单元**并存**，链上显示为一处"断层"，之后由引用、使用与检验决定可信度消长。争议是认知提升的关键，机制要保护它，而不是消灭它。

- 竞争单元以**取代**引用表达挑战；
- 新旧单元并存，双方都保留历史与署名；
- 被取代的单元不再向依据它的单元传递可信度；
- **不强行裁决**：立场之争永不裁决，链只记录谁持何观点、理由是什么。

### 5.3 核验人指派

每个版本由协议确定地指派核验人（种子取自发布该版本的区块哈希、单元号与版本号）：**发布者事先无法预知，任何人都能复核同样的结果**。只有被指派者的结论计入可信度。

> 当前实现状态：指派算法已实现并在浏览器中提示（`/assign`），链仍接受所有成员的核验。改为共识强制需按高度激活，排在主网上线前完成。

## 6. 代币经济学

### 6.1 代币

| 代币 | 作用 | 供应 |
|---|---|---|
| $COG | 维护这份公共信任的成本的计价单位；结算、治理、激励 | **锚定知识量**：知识增加则增发，知识退场则销毁 |
| cNFT | 认知贡献证书，记录具体贡献，不可分割 | 按贡献铸造 |

> 早期设计中的 $WATT（电力凭证）与 $FLOP（算力凭证）已降级为未来方向，见 §12.2。

### 6.2 供应锚定知识量

```
知识量 K = Σ 已确立在册单元的 min(有效可信度, 0.6) × min(√重要性, 3)
目标供应量 M* = k × K
每期净变化 = 前馈（跟随 K 的增长） + 纠偏（比例 + 积分，纠偏有上限）
```

四条硬约束：

1. **只从资金流里销毁**（外部付费、租金税、罚没），**绝不动任何账户的余额**；
2. **按规则自动调节**，任何人能预先算出下一期结果；治理只能调系数，且有生效延迟；
3. **收缩有速度上限**（每期 0.5%），防止一次冲击引发剧烈通缩；
4. **知识是否存活看使用，不看钱**。

### 6.3 分配

```
来源：协议增发（锚定知识量）+ 外部付费（检索费等）+ 罚没
  │
  ├─ 60%  知识奖励池 → 按重要性分给已确立单元 → 其中 20% 沿"依据"上溯给被引用的单元
  ├─ 25%  核验奖励池 → 按当期核验得分分给核验人
  └─ 15%  国库 → 公共开支、新人基金

所有收益先锁定 6 期再释放；锁定期内被挑战成功（含当时就能查出的错误），
作者与放行的核验人锁定中的收益被罚没：一半奖励挑战者，一半销毁。
```

**仿真得出的最重要一条**：核验必须有报酬。不付核验报酬时，诚实成员用于核验的精力从 68% 降到 24%，能完成核验的单元从 38% 降到 5%——知识库几乎停止增长。

### 6.4 与主网的关系

测试网**不发行任何代币**。测试网积累的知识与核验记录将作为主网的启动数据；代币余额不迁移，信誉由主网按主网规则从迁移的记录重新计算。**不提前承诺任何兑换关系**——否则测试网会成为刷分目标，而测试网恰是防御最弱的时候。

## 7. 与夜莺社区其他产品的关系

知行图是社区产品体系中的**知识共识层**。按社区的[产品关系与开发边界](https://github.com/yeying-community/books/blob/main/yeying/%E5%A4%9C%E8%8B%AF%E7%A4%BE%E5%8C%BA/%E4%BA%A7%E5%93%81/%E4%BA%A7%E5%93%81%E7%BB%84%E5%90%88/%E7%A4%BE%E5%8C%BA%E4%BA%A7%E5%93%81%E6%9E%B6%E6%9E%84.md)，三者职责不重叠：

```
Wallet          →  身份与签名：用户的密钥在钱包里，钱包签知识 op、签授权
Knowledge       →  知识生产：把资料整理成知识项，做检索、证据与运行记录
知行图（链）    →  知识共识：谁能发布、谁核验了谁、可信度多少、这些事实的最终性
```

| 能力 | 事实源 | 其他项目如何使用 |
|---|---|---|
| 用户密钥、签名、站点权限 | **Wallet** | 钱包签发知识 op；知行图只**验证**签名，不管理密钥 |
| 链账户与身份的关联 | **Wallet**（DID `did:yeying:wid_*` + 账户关联证明） | 知行图的成员账户可关联到钱包身份，供审计与治理使用 |
| 私有资料、检索、Evidence、Agent Run | **Knowledge** | 知行图不复制这些对象 |
| 文件内容 | **Warehouse** | 正文仓库与文件资产同源 |
| 知识单元、版本、引用、核验、可信度 | **知行图** | Knowledge 可引用链上已发布的知识项作为**已验证来源** |
| 模型调用与计量 | **Router** | 与知识链无关 |

### 7.1 两条边界

**边界一：私有草稿 vs 公开共识。**
Knowledge 拥有组织内部**私有、仍在编辑中**的知识；知行图拥有**已发布、要被外部引用、要有人担保**的知识。一条知识从 Knowledge 走到链上，是一个显式的**发布**动作；发布之后，它的核验记录永久在链上。发布不是复制——链上只存哈希与结构，正文仍在仓库。

**边界二：链不接管既有系统。**
知行图不替代 Knowledge 的检索与证据体系，也不替代 Wallet 的身份与授权流程。它提供的是这两者都缺的东西：**跨组织的、公开的、带最终性的"谁担保了什么"**。

**已落地的一条连接：夜莺钱包原生支持知行图。** 这正是上表"钱包签发知识 op；知行图只验证签名"的实现：
钱包保管成员的知行图密钥（派生与 `node keygen` 相同，用既有助记词导入就是原来那个链上账户），
网页只递"意图"（谁、第几条、做什么），**钱包自己编码、在弹窗里显示可读摘要（例如"核验单元 #8 的 v2：通过"）、
确认后签名**——用户看到的就是实际签的内容。知行图密钥不是钱包里的资产账户（没有余额），单独保存、
用钱包密码加密、按网站授权。成员密钥与钱包 DID 的绑定目前不排期（理由见 §11 阶段 2）。

### 7.2 为什么这个组合有意义

- **Knowledge 解决"写得快、找得到"；知行图解决"别人凭什么信"。** 前者是效率问题，后者是信任问题。
- **钱包签、链验**：链上不存私钥，只存签名；用户的密钥始终在钱包里（知行图的签名算法是 ed25519，钱包的多链适配器已支持该曲线）。
- **跨组织可用**：Knowledge 的知识只在组织内可信；当它要对外提供、被第三方引用、被模型训练集采用时，需要一层**跨组织的公共担保**。

## 9. 认知地形图

借鉴地理信息系统（GIS），把知识图谱渲染为可导航的地形：

| 地形元素 | 认知含义 | 计算方式 |
|---|---|---|
| 峰 (Peak) | 核心共识命题 | 引用数 × 验证人数 × 时间累积 |
| 高原 (Plateau) | 成熟稳定领域 | 邻居密度高 + 边权重稳定 |
| 山脊 (Ridge) | 跨领域桥梁 | 连接多个高密度子图的节点 |
| 山谷 (Valley) | 认知空白 | 低密度 + 孤立节点群 |
| 陡坡 (Cliff) | 范式转换 | 短期内边权重剧变 |
| 断层 (Fault) | 认知冲突 | 高"取代"关系 + 并存的竞争单元 |

**任何人都能通过这张地图看到人类认知的全貌，找到自己能贡献的"山谷"**——这正是知行图激励机制的意义所在。

> **配套的探索能力**(已上线):从任意单元可看**它的地基与继承**(谁建立在它之上、它站在谁之上,按距离分层);
> 以及**缺口视图**——哪些单元还没有被任何人依据、也还没有人核验,它们就是图里的山谷。缺口与覆盖按领域汇总,
> 让人知道该往哪里补。
>
> 实现路径：地形是知识图的**可视化投影**，不改变底层数据模型，也不新增任何链上状态。
> **已上线**：浏览器"地形图"页把链上的引用关系（依据 / 参见 / 取代）与可信度投影成地形——
> 横轴分领域，纵轴为层级（基础在下），高度是可信度与被引用程度，颜色是地形类型（峰 / 高原 / 山脊 / 山谷 / 断层），
> 点开任一节点可看它的地形属性与引用关系。数据全部来自链上已有的引用与核验记录。
> 当前是 2D 投影；真正的 3D 地形渲染是后续的呈现层升级。

## 10. 治理

- **参数调节**：增发基准、核验门槛、等领域参数由链上提案调节，**双门槛**通过；
- **声誉加权**：治理投票结合领域声誉，避免纯资本主导；
- **认知宪法**：明确"什么算认知贡献"的元规则，修改需超级多数 + 冷静期；
- **创始社区无豁免**：早期每个判断都可被挑战，信誉同样随时间衰减（见 §4.4）。

## 12. 风险与开放问题

### 12.1 已知风险

| 风险 | 现状与缓解 |
|---|---|
| **认知的主观性** | 不追求"客观"，追求"可解释、可追溯、有担保人"。争议以竞争单元并存，由证据与使用分高下 |
| **社区把关能力不足** | 早期由小规模创始社区把关；仿真显示大规模作恶时经济机制挡不住，防线是准入（邀请担保、见习期）。主网开放程度须与把关能力匹配 |
| **核验被少数人垄断** | 核验人随机指派；信誉随时间衰减；创始社区无豁免 |
| **知识被大规模复制** | 同一正文不能重复建单元；引用与核验记录无法伪造 |
| **链上无正文** | 链只承诺哈希；正文在内容寻址仓库，任何人可取回并自行校验。这是刻意的取舍：可读性优先于链上冗余 |
| **测试网被刷分** | 测试网不发行代币、不承诺兑换；余额不迁移 |
| **代币被套利** | 经济参数由仿真标定但**必须与真实数据交叉校准**；参数可经治理调整 |

### 12.2 未来方向：认知的物理锚定（PoE / PoF）

早期版本的白皮书提出**三层价值映射：电力 → 算力 → 认知**，并要求代币同时锚定真实流过的绿色电力与真实运行的有效算力（PoE / PoF）。

**已决定（2026-11-15）：暂不推进，把资源集中在知识基础设施。** 三层需要绿证供应商与电网数据接口、需要 TEE 与 zkML/opML 的可验证计算基础设施——**这些都不是社区现有的能力**，wallet 与 knowledge 也不覆盖。继续推进会让项目看起来像在做"绿色算力认证"，而不是知识基础设施。

因此本稿将其降级为未来方向，并保留两项可行性研究（附录 B.4、B.5）作为技术存档：
- Energy Oracle 与绿证体系的对接标准（B.4）；
- zkML / opML 在 PoF 中的可行性评估（B.5）；

代币的锚定物**当前是知识量**（§6.2），这已经满足"锚定真实投入"的要求。若未来出现明确的绿证合作方与资金，可讨论是否把"认知的物理投入"作为**附加约束**（例如要求大额增发附带资源证明），而不改变主线的知识锚定。

### 12.3 开放问题

1. **可理解性如何衡量**？当前靠"自身能读懂"的原则与人工评审，缺可测指标。
2. **模型生成内容的标注与核验流程**，如何避开编造与模型自身的幻觉？
3. **多贡献者的收益分配**：作者、修订者、翻译者、核验者之间如何分？
4. **链下正文由谁存储**？当前是内容寻址仓库，长期需要多副本与可用性保障。
5. **模型用这份数据训练后，收益如何回流**？
6. **跨领域的本体如何标准化**（B.6）？——词表 v0.1 已实现（JSON-LD，复用 schema.org / PROV-O / Dublin Core / SKOS）；领域由谁定义、如何演进仍开放。
7. **与 AI Agent 的关系**：Agent 能否成为知识单元的作者？其贡献如何归属（§4.4 的机构与 Agent 静默期处理）？

## 13. 结语

> **知行图要做的不是一条更快的链，而是一层新的公共设施：让人类和大模型写下的一切，都可被人类解释。**
>
> 当一条结论可以被追溯到它的来源、它的依据、以及为它负责的人，它才可以被复用、被审计、被继承。
> 到那时，人类拥有了一个不是由任何机构垄断的**公共知识底座**——机器可以从中取材，人可以从中判断。
>
> $COG 是维护这份底座的成本的计价单位。它锚定知识量：知识增加就增发，知识退场就销毁。
> 它不是投机标的的理由，它是一句关于"什么值得被维护"的回答。

知行，知行合一。

### B.1 PoK 共识的博弈论建模与攻击面分析

#### B.1.1 参与者与博弈结构

PoK 是一个多阶段、不完全信息的重复博弈。核心参与者及其策略空间：

| 参与者 | 策略空间 | 收益来源 | 成本 / 风险 |
|---|---|---|---|
| 贡献者 (Contributor) | {提交真实贡献, 伪造/抄袭, 灌水} | $COG 铸造 + cNFT | 质押 `S_c`、被罚没、声誉损失 |
| 评议人 (Reviewer) | {认真评议, 偷懒随机打分, 合谋} | 评议奖励 + 声誉增值 | 抽选质押、错误评议的声誉衰减 |
| 挑战者 (Challenger) | {提交有效反驳, 不参与, 恶意挑战} | 罚没分成 | 挑战质押 `S_ch` |
| 验证人/复现者 | {独立复现, 谎报复现} | 复现奖励 | 算力成本、谎报被发现的罚没 |

单轮博弈的贡献者期望收益：

```
E[U_contributor] = P_accept · (mint(ΔK) + value(cNFT))
                 − (1 − P_accept) · slash(S_c)
                 − cost_produce
```

设计目标：使 `诚实提交` 成为**子博弈精炼纳什均衡（SPNE）**，即对任意理性参与者，偏离诚实策略的期望收益为负。

#### B.1.2 攻击面清单与对策

| # | 攻击 | 机理 | 对策 | 博弈论依据 |
|---|---|---|---|---|
| A1 | 女巫攻击 (Sybil) | 单实体控制多身份刷贡献/评议 | 声誉不可转让 + 领域声誉需长期积累 + 抽选按声誉加权 | 制造有效身份的边际成本 > 边际收益 |
| A2 | 评议合谋 (Collusion) | 评议人串通抬高/压低分数 | VRF 随机抽选 + 利益回避 + 二次方评议 + 事后复现挑战 | 合谋需贿赂 ≥ 多数被抽中者，成本随抽样池指数上升 |
| A3 | 懒惰评议 (Lazy) | 不审直接给均值分套取奖励 | 引入"预测市场式"评分：偏离最终共识越远，奖励越低（peer-prediction / BTS 机制） | 说真话为占优策略 |
| A4 | 贿赂 / 暗箱 (Bribery) | 场外收买评议人 | 提交—评议采用 commit–reveal，评议前不知贡献者身份 | 提高协调与信任成本 |
| A5 | 随机数操纵 (Grinding) | 操纵抽选以选中同伙 | VRF + 未来区块熵作为种子，抽选结果不可预测/不可事后操纵 | 消除操纵杠杆 |
| A6 | 抄袭 / 重复提交 | 换皮已有认知骗取 ΔK | novelty 用语义嵌入 + 图距离检测近重复；引用溯源 | 使 `novelty ≈ 0`，ΔK 归零 |
| A7 | 抢跑 (Front-running) | 抢先提交他人预印内容 | 时间戳承诺（commit hash 先行）+ 原创性溯源 | 先承诺者得优先权 |
| A8 | 罚没规避 | 贡献者拿钱后弃质押 | 质押锁定期覆盖挑战期 + 声誉长期绑定 | 使违约净收益为负 |

#### B.1.3 关键激励约束（待形式化验证）

- **诚实提交约束**：`P_accept·mint(ΔK) − (1−P_accept)·slash(S_c) − cost > 灌水策略收益`
- **诚实评议约束（peer-prediction）**：评议奖励 `R_review = f(与后验共识的一致性)`，使 `E[R|诚实] > E[R|随机]`
- **挑战有效性约束**：`slash 分成 > S_ch`，保证有利可图，但恶意挑战因需自押而被抑制

> ⚠️ 开放问题：peer-prediction 机制在评议人数量少、领域高度专业化时的稳健性；VRF 抽样池过小导致的合谋阈值下降。需在 B.3 仿真中回归。

### B.2 ΔK 计算公式的形式化定义与参数标定

#### B.2.1 形式化定义

正文 §5.2 给出 `ΔK = novelty × correctness × reproducibility × domain_gap_bonus`。此处形式化每个因子，值域统一归一到 `[0,1]`（bonus 除外，取 `≥1` 的乘子）。

设已有认知图谱为 `G = (V, E)`，新提交贡献为节点 `x`，其语义嵌入为 `emb(x) ∈ ℝ^d`。

**(1) 新颖度 novelty ∈ [0,1]**

```
novelty(x) = 1 − max_{v ∈ N_domain(x)} cos_sim(emb(x), emb(v))
```

- `N_domain(x)`：同领域候选邻居集合（近似最近邻检索，如 HNSW）；
- 近重复（`cos_sim > τ_dup`，建议 `τ_dup = 0.95`）直接判定 `novelty = 0`（对应 A6 抄袭）。

**(2) 正确性 correctness ∈ [0,1]** —— 声誉加权的贝叶斯聚合

设评议人 `i` 声誉 `r_i`，打分 `s_i ∈ [0,1]`：

```
correctness = Σ_i (r_i · s_i) / Σ_i r_i
```

进一步可用 Beta-Binomial 后验建模，输出均值与置信区间；置信区间过宽（评议不足）时触发追加评议。

**(3) 可复现性 reproducibility ∈ [0,1]**

```
reproducibility = (成功独立复现数) / (总复现尝试数)
```

- 无需复现的理论型命题：由评议共识度 `agreement` 代理，`reproducibility := agreement`；
- 复现尝试数不足阈值 `n_min` 时，因子封顶（如 ≤ 0.7），避免"未经充分检验即高分"。

**(4) 跨域桥接奖励 domain_gap_bonus ≥ 1**

```
domain_gap_bonus = 1 + λ · (连接的独立子图数 − 1) · avg_gap
```

- `avg_gap`：被桥接子图间在图谱中的平均最短路径距离（越远越稀缺）；
- `λ`：桥接激励系数，`λ ∈ [0, λ_max]`，由治理设定上限防刷。

**最终**（含时间因子，鼓励尽早填补山谷，呼应 §6.2 `time_decay`）：

```
ΔK(x) = novelty · correctness · reproducibility · domain_gap_bonus · time_freshness
```

#### B.2.2 参数标定方法论

| 参数 | 初始建议 | 标定方法 |
|---|---|---|
| `τ_dup` | 0.95 | 用已知抄袭/原创对构造标注集，选 F1 最优阈值 |
| `n_min`（最少复现） | 2 | 按领域复现成本分层设定 |
| `λ`（桥接系数） | 0.3 | 仿真扫描，使跨域贡献占比达目标区间（如 15–25%） |
| `α, β, γ`（§3.1 权重） | 0.2 / 0.3 / 0.5 | 治理初值 + 反馈控制（见下） |

**闭环标定（反馈控制）**：将参数视为控制变量，以生态健康指标（基尼系数、山谷填补率、伪贡献率）为被控量，用离线仿真（B.3）→ 测试网 A/B → 治理提案的方式迭代收敛。

#### B.2.3 可实现规范（Implementable Spec）

为使 B.3 仿真与后续实现能直接落地，此处钉死 ΔK 的输入接口、归一化与边界情形。这是 §5.2 公式的**规范化版本**，是 B.1/B.3/§6 的共同依赖。

**输入接口**：`compute_delta_k(submission, graph, reviews, replications, params) -> float`

| 输入 | 类型 | 来源 |
|---|---|---|
| `submission.embedding` | `float[d]` | Cognition Engine 抽取 |
| `submission.domain` | `str` | 提交声明 + 本体校验（B.6）|
| `submission.timestamp` | `int` | 链上区块时间 |
| `graph` | 图谱句柄 | 状态层，支持同域近邻检索 |
| `reviews` | `[(reviewer_rep, score)]` | PoK 评议阶段 |
| `replications` | `(success, total)` | PoK 复现挑战阶段 |
| `params` | dict | 治理参数（下表）|

**归一化与边界规则**（全部因子在此夹紧，避免异常放大）：

| 因子 | 计算 | 边界 / 缺省 |
|---|---|---|
| `novelty` | `1 − max cos_sim(x, 同域近邻)` | 域内首节点（无邻居）→ `novelty = 1`；`cos_sim > τ_dup` → `0` |
| `correctness` | `Σ rᵢsᵢ / Σ rᵢ` | 评议数 `< n_review_min` → 因子封顶 `c_cap`（如 0.5），并触发追加评议 |
| `reproducibility` | `success / total` | 理论型（`total=0`）→ 取评议一致性 `agreement`；`total < n_min` → 封顶 0.7 |
| `domain_gap_bonus` | `1 + λ·(bridged−1)·avg_gap` | 无跨域 → `1.0`；夹紧到 `[1, bonus_max]` |
| `time_freshness` | `exp(−decay · age_days)` | 夹紧到 `[fresh_min, 1]` |

**统一治理参数表**（仿真与实现共用同一份默认值）：

```
τ_dup        = 0.95   # 近重复阈值
n_review_min = 3      # 最少评议人数
c_cap        = 0.5    # 评议不足时 correctness 上限
n_min        = 2      # 最少复现尝试
λ            = 0.3    # 跨域桥接系数
bonus_max    = 2.0    # 桥接奖励上限
decay        = 0.01   # 时间衰减率 (per day)
fresh_min    = 0.5    # 时间因子下限
delta_k_min  = 0.05   # ΔK 阈值，低于此视为 0（不铸币）
```

**参考实现（伪代码）**：

```python
def compute_delta_k(sub, graph, reviews, repl, p):
    # 1. novelty
    nbrs = graph.knn(sub.embedding, sub.domain, k=32)
    if not nbrs:
        novelty = 1.0
    else:
        max_sim = max(cos_sim(sub.embedding, v.embedding) for v in nbrs)
        novelty = 0.0 if max_sim > p.tau_dup else (1.0 - max_sim)

    # 2. correctness (reputation-weighted)
    if len(reviews) < p.n_review_min:
        correctness = min(weighted_mean(reviews), p.c_cap)   # + 触发追加评议
    else:
        correctness = weighted_mean(reviews)                 # Σrᵢsᵢ / Σrᵢ

    # 3. reproducibility
    success, total = repl
    if total == 0:
        reproducibility = agreement(reviews)                 # 理论型
    else:
        r = success / total
        reproducibility = min(r, 0.7) if total < p.n_min else r

    # 4. cross-domain bonus
    bonus = clamp(1 + p.lam * (bridged_subgraphs(sub, graph) - 1)
                    * avg_gap(sub, graph), 1.0, p.bonus_max)

    # 5. freshness
    fresh = clamp(exp(-p.decay * age_days(sub)), p.fresh_min, 1.0)

    dk = novelty * correctness * reproducibility * bonus * fresh
    return dk if dk >= p.delta_k_min else 0.0    # 阈值门控 → 不铸币
```

> **契约**：`compute_delta_k` 为纯函数（无副作用），输出 `∈ [0, bonus_max]`；`return 0.0` 即 §3.2 硬约束"ΔK≤0 不增发"的落点。B.3 仿真必须调用此同一函数，确保文档与仿真一致。

> ⚠️ 开放问题：语义嵌入模型本身可被攻击（对抗样本抬高 novelty）；需嵌入模型版本治理与对抗鲁棒性评估。

### B.3 $COG 增发/销毁的经济仿真（agent-based simulation）

#### B.3.1 仿真目标

回答三个问题：(1) $COG 供应在何种参数下保持长期稳定而非恶性通胀/通缩；(2) 激励是否真的引导资源流向"认知山谷"；(3) 各类攻击（B.1）在经济层面的可行性与破坏度。

#### B.3.2 智能体与状态

| Agent 类型 | 关键状态 | 决策规则 |
|---|---|---|
| 诚实贡献者 | 余额、声誉、领域偏好 | 依 `E[U]` 选择投入领域与强度 |
| 投机/灌水者 | 余额、风险偏好 | 尝试低成本高频提交，遇罚没即退出 |
| 评议人 | 声誉、专业领域 | 认真/懒惰视奖励结构而定 |
| 电力/算力提供者 | 产能、价格 | 依 $WATT/$FLOP 供需定价 |
| 认知消费者 | 需求、预算 | 消费认知服务 → 销毁 $COG |

#### B.3.3 仿真循环（每 epoch）

```
for epoch in 1..T:
    1. 提供者上报电力/算力 → 铸造 $WATT/$FLOP
    2. 贡献者根据预期收益提交贡献（消耗资源）
    3. PoK：抽选评议 → 挑战 → 计算 ΔK
    4. ΔK>0 → mint($COG)；ΔK≤0 → slash
    5. 消费者消费服务 → burn($COG)
    6. 更新声誉、价格、图谱拓扑
    7. 记录指标
```

#### B.3.4 观测指标

- **货币**：$COG 净增发率、流通量、（模拟）价格波动率；
- **公平**：贡献者收益基尼系数、声誉集中度（HHI）；
- **认知健康**：山谷填补率、跨域边占比、图谱平均置信度；
- **安全**：伪贡献通过率、合谋 ROI、攻击者净收益。

#### B.3.5 场景矩阵

| 场景 | 变量 | 期望结论 |
|---|---|---|
| 基线 | 默认参数 | 供应稳定、收益分散 |
| 通胀压力测试 | 提高 base_emission | 找到不失控上限 |
| 女巫/合谋 | 注入 10–40% 恶意 agent | 攻击 ROI 应为负 |
| 冷启动 | 稀疏初始图谱 | 验证早期激励（time_decay/bonus）有效性 |
| 熊市 | 消费需求骤降 | 通缩机制不致螺旋崩溃 |

#### B.3.6 技术实现建议

Python + [Mesa](https://mesa.readthedocs.io/) 或 [AgentPy] 起步；参数扫描用网格 / 贝叶斯优化；输出接 §B.2 的闭环标定。

#### B.3.7 原型仿真结果（Milestone 2）

已实现一个**零依赖**（纯 Python 标准库）的 ABM 原型，代码见仓库 [`sim/`](../sim/)。仿真直接调用 B.2.3 定义的同一个 `compute_delta_k` 函数，保证文档与代码使用同一份契约。运行方式：`python3 sim/run.py`。

场景矩阵（B.3.5）在默认参数、`seed=42`、200 epoch 下的结果：

| 场景 | 供应(创世→末期) | 净增发/ep | Gini | 跨域均衡 | 伪贡献通过率 | 攻击者净回报 | 诚实净回报 |
|---|---|---|---|---|---|---|---|
| baseline | 1200 → 1790 | +1.9 | 0.041 | 0.93 | 0.0 | — | +0.59 |
| inflation_stress | 1200 → 14899 | +48.0 | 0.041 | 0.93 | 0.0 | — | +2.73 |
| sybil_collusion | 1650 → 2120 | +1.3 | 0.391 | 0.90 | 0.0 | **−0.29** | +0.58 |
| cold_start | 240 → 443 | +0.7 | 0.026 | 0.83 | 0.0 | — | +1.04 |

> 净回报 = `(累计奖励 − 累计罚没) / 累计质押`，`< 0` 表示净亏损；伪贡献通过率取末 20 epoch 均值。

**关键发现：**

1. **攻击不经济**（核心结论）：在注入 15 spammer + 10 colluder 的 `sybil_collusion` 场景下，**攻击者净回报为 −0.29（亏损），而诚实者为 +0.58**；伪贡献通过率随声誉衰减机制作用在末期收敛到 0。这为 B.1 的激励约束提供了初步经验支持——偏离诚实策略的期望收益为负。
2. **ΔK 门控有效**：`delta_k_min` 阈值 + 近重复检测使绝大多数低质/重复提交 `ΔK=0`、不铸币且被罚没。
3. **增发上限确有必要**：`inflation_stress`（base_emission 调至 4×）令供应 12× 膨胀，印证 §6.2 需要 `base_emission` 治理上限与反馈控制。
4. **无死锁**：`demand_shock`（需求崩溃）导致供应膨胀但系统不停摆，诚实激励延续；`cold_start`（仅 8 名贡献者）仍能自举图谱（跨域均衡 0.83）。
5. **收益分散**：无攻击场景 Gini ≈ 0.04（高度均衡）；攻击场景升至 0.39，反映攻击者早期套利——这也指示需进一步强化早期检测。

**局限（诚实声明）**：此为方向性原型而非标定模型；语义嵌入用随机向量代理、未建模对抗样本；需求端为简化流量代理。结论须与测试网数据校准后方具外推力（对接 B.3.6 与 §B.2 闭环标定）。详见 [`sim/README.md`](../sim/README.md)。

> ⚠️ 开放问题：ABM 结论对行为假设敏感，需与真实测试网数据校准后才有外推效力。

### B.4 Energy Oracle 与绿证体系的对接标准

#### B.4.1 目标

为 PoE 提供**可信、防篡改、防重复计算**的电力数据，且能证明其"绿色属性"，将物理 kWh 映射为链上 `E_audit`。

#### B.4.2 数据模型（PoE 声明）

```json
{
  "meter_id": "did:meter:0x...",
  "period": {"start": 1789000000, "end": 1789003600},
  "energy_kwh": 1024.7,
  "green_certificates": [
    {"scheme": "I-REC", "cert_id": "IREC-...", "mwh": 1.0, "retired": true}
  ],
  "green_ratio": 0.92,
  "location": "geohash:wx4g0",
  "signature": "device_sig:...",
  "zk_proof": "zk:range+authenticity"
}
```

#### B.4.3 绿证体系对接

| 体系 | 区域 | 对接要点 |
|---|---|---|
| I-REC | 国际 | 证书须标记 `retired`（已注销），防重复出售 |
| GEC（绿电证书） | 中国 | 与国家平台核销状态对账 |
| GO / REC | 欧盟 / 北美 | 时间与地理匹配（24/7 CFE 理念） |

**核心规则**：1 份绿证只能锚定一次 `green_ratio` 提升；核销状态由 Oracle 实时核对，已注销证书方可入账。

#### B.4.4 可信采集与防伪

- **硬件**：智能电表内置安全芯片（Secure Element），数据出厂即签名；
- **传输**：设备签名 + 时间戳，Oracle 多源交叉验证（电表读数 vs 电网结算 vs 卫星/碳排数据）；
- **隐私**：用 ZK 范围证明披露"kWh 落在区间且证书有效"，而不暴露商业敏感的精确用电曲线；
- **防重复计算**：`(meter_id, period)` 唯一性约束 + 绿证注销状态双重校验。

#### B.4.5 标准草案要点

1. PoE 声明 Schema（上）作为链上标准结构；
2. Oracle 节点去中心化 + 抵押 + 错误上报罚没；
3. 与至少一个绿证注册平台的 API 核销对接规范；
4. 争议仲裁：数据异常触发挑战 → 多 Oracle 复核。

> ⚠️ 开放问题：绿电的"时间/地理匹配"严格程度（年度配额 vs 24/7 实时匹配）直接影响成本与可信度，需分阶段收紧。

### B.5 zkML / opML 在 PoF 中的可行性评估

#### B.5.1 待证明的命题

PoF 要证明："声明消耗的算力确实执行了指定的、有效的计算任务（训练/推理），而非空转或替换为廉价任务"。

#### B.5.2 三条技术路线对比

| 维度 | TEE（SGX/TDX） | zkML | opML（乐观式） |
|---|---|---|---|
| 信任假设 | 信任硬件厂商 | 纯密码学（最强） | 经济博弈 + 挑战期 |
| 证明开销 | ≈1×（近原生） | 10³–10⁶×（当前）| ≈1×（乐观执行） |
| 验证开销 | 远程认证 | 亚秒级、极小 | 仅争议时重算 |
| 延迟 | 低 | 高（生成慢） | 低（乐观即时，终局延后） |
| 成熟度 | 高，已商用 | 快速发展，受限于模型规模 | 中，已有实现 |
| 适用规模 | 大模型可行 | 目前限中小模型/算子 | 大模型可行 |
| 主要风险 | 侧信道、厂商信任 | 成本、算子覆盖不全 | 挑战期资金锁定、需活跃验证者 |

#### B.5.3 分阶段策略（混合方案）

```
Phase 1  以 TEE 为主：远程认证 + 度量执行环境，快速可用
Phase 2  引入 opML：对高价值任务加挑战期，降低对硬件的单点信任
Phase 3  关键/高敏任务用 zkML：对可承受成本的核心算子给出密码学证明
长期     TEE-in-ZK / 硬件加速 zkML 成熟后逐步提升 zk 覆盖率
```

#### B.5.4 与 ΔK 的耦合

PoF 不单独增发 $COG（§3.2 硬约束）——它产出 `F_useful` 作为 ΔK 计算的资源背书；即使 PoF 完美，`ΔK=0` 仍不铸币。因此 PoF 的可行性门槛可适度放宽：**用较低成本证明"算力用于真实任务"即可，不必对每一步 FLOP 做零知识证明。**

> ⚠️ 开放问题：zkML 对 Transformer 类大算子的证明成本仍偏高；opML 挑战期与主网终局性的权衡需结合 B.1 攻击面分析确定参数。

### B.6 知识互操作词表（原"认知图谱本体标准草案"）

> **状态（2026-11-20）：v0.1 已实现并上线**，规范见 [`docs/design/ontology-v0.1.md`](design/ontology-v0.1.md)。
> 本节早期草案面向"命题图谱"（ENTAILS / REFUTES 等边、PoE/PoF 溯源）；链上实际运行的是**知识单元模型**
> （§3、§4），PoE/PoF 已决定暂不推进（§12.2），所以本节按现行模型重写，原"三层本体"思路作为背景保留。

#### B.6.1 目标

让链上的知识事实——谁写的、依据什么、谁核验过、可信度多少、有没有被取代——能被链以外的系统直接使用：
检索系统、知识库、大模型训练与评测、其他组织的知识图谱。

#### B.6.2 做法

- **格式**：JSON-LD 1.1。任何 JSON-LD 处理器都能展开成 RDF、用 SPARQL 查询。
- **复用标准**：schema.org（作品、正文、评审）、W3C PROV-O（作者、生成活动、模型、核验活动）、
  Dublin Core（版本、引用、取代、许可）、SKOS（领域、层级、生命周期的概念方案）。
  只为这些标准里没有的概念新造词（`kdg:` 命名空间下 3 个类、约 20 个属性）：知识单元、版本、核验，
  依据关系（可信度沿它传递）、来源类型、可信度。
- **标识**：`https://blockchain.yeying.pub/id/unit/{n}`、`…/unit/{n}/v/{m}`、`…/member/{n}`、`…/domain/{n}`；
  主网迁移时不变，可直接打开。
- **引用指向具体版本**：依据锁定被引版本，被引单元以后修订，引用不会悄悄改变含义。

#### B.6.3 与早期草案的对应

| 早期草案 | 现行 |
|---|---|
| 上层本体 Concept / Proposition / Evidence / Actor | 知识单元 / 版本 / 正文与核验 / 成员与模型 |
| 领域本体（ai/、math/ …命名空间隔离） | 领域概念方案（SKOS），链上用编号，名称在 `domains.jsonld` 唯一定义 |
| 复用 SKOS / PROV-O / DID / JSON-LD | 已复用；成员标识按链上账户号，钱包身份 DID 的关联留待后续 |
| 边 ENTAILS / REFUTES / CITES / EXTENDS / DISPUTES | 依据（`kdg:basedOn`）/ 参见（`rdfs:seeAlso`）/ 取代（`dcterms:replaces`）；观点相左用"竞争单元"表达，不设反驳边 |
| 边 POWERED_BY / ENERGIZED_BY（PoE/PoF） | 不做（§12.2） |
| 本体变更走链上提案 | v1 内只增不改；改变含义发布 v2，v1 继续可用 |

#### B.6.4 跨组织：从 Knowledge 发布到知行图

社区的知识生产工作台 Knowledge 可以把条目「上链到知行图」：首次上链创建单元，之后的修订发布为新版本；
签名在浏览器里由夜莺钱包完成，Knowledge 不接触私钥。字段对应见规范 §8。

> ⚠️ 开放问题（保留）：领域本体由谁定义、如何避免成为认知垄断工具——现阶段领域随创世参数确定，
> 增加领域需要治理；更开放的领域演进机制需与治理一起设计。
