## 知行图是什么

知行图是夜莺社区的**知识共识层**：一张公开的、可验证的人类知识图。它把"人类和大模型写下的每一条知识"变成
带版本、带来源、带引用、带核验记录的结构化单元，让任何一条结论都能追溯到：谁写的、依据什么、谁担保过、
后来有没有被推翻。

**一句话**：Knowledge 解决"写得快、找得到"，知行图解决"别人凭什么信"。

## 目标读者与使用条件

- **知识使用者**：任何人都可以免费阅读、检索与导出（CC BY 4.0），无需账户；
- **成员**：通过邀请加入，可写作、修订、核验与邀请；新成员有见习期，期间核验不计入可信度；
- **应用开发者**：通过公开 API 读取知识与可信度，或导出全部单元用于检索与训练。

## 用户价值

- 一条结论附带**来源**（人工撰写 / 模型生成+模型名与版本 / 模型生成且人工修改过）与**依据**（它建立在哪些更早的结论之上）；
- **可信度是算出来的**：等于合格核验人的认可数，且不超过它所依据的地基——任何人可从链上数据独立重算；
- **挑战不靠举报**：提交竞争单元，新旧并存，由证据与使用随时间分高下；
- 正文由内容哈希承诺，浏览器取回后**重新计算哈希**比对，内容无法被悄悄替换。

## 核心对象与数据归属

| 对象 | 说明 | 事实源 |
|---|---|---|
| 知识单元 | 一条只讲一件事的知识；层级、版本、来源、引用 | 知行图 |
| 核验记录 | 谁在哪个高度核验了哪个版本、结论如何 | 知行图 |
| 可信度 | 由核验记录与依据关系派生 | 知行图（派生值，可重算） |
| 成员关系 | 邀请人、加入高度、见习期 | 知行图 |
| 正文 | 知识单元的文本内容 | 内容寻址的正文仓库（链上只存 SHA-256） |
| 签名密钥 | 成员的 ed25519 私钥 | 夜莺钱包（网页不持有、不保存私钥）；命令行工具用本地密钥文件 |

## 与其他产品的边界

| 产品 | 关系 |
|---|---|
| **Wallet** | 钱包管用户密钥与签名，**签发**知识 op；知行图只**验证**签名，不管理密钥。签名算法 ed25519，钱包多链适配器已支持该曲线 |
| **Knowledge** | Knowledge 拥有组织内部**私有、仍在编辑中**的知识（草稿、检索、Evidence、Agent Run）；知行图拥有**已发布、要被外部引用、要有担保**的知识。一条知识从 Knowledge 发布到链，是一个显式动作 |
| **Warehouse** | 文件内容的事实源；知行图的正文仓库可与之同源 |
| **Node** | 社区应用登记与授权入口；知行图作为一个社区服务登记 |
| **Router** | 无直接关系 |

**两条边界**：

1. **私有草稿 vs 公开共识**：发布不是复制——链上只存哈希与结构，正文仍在仓库；
2. **链不接管既有系统**：知行图不替代 Knowledge 的检索与证据体系，也不替代 Wallet 的身份与授权流程；
   它提供两者都缺的东西——跨组织的、公开的、带最终性的"谁担保了什么"。

## 典型流程

1. 成员把自己的密钥导入夜莺钱包（「账户管理 → 导入钱包 → 知行图」），在网页上用钱包登录；
2. 写作：编辑正文 → 上传到正文仓库 → 签名"创建单元"操作 → 提交上链；
3. 核验：其他成员阅读正文、逐条确认"核验要点"后给出"通过"或"需修改"；
4. 可信度自动更新；依据它的上层单元的有效可信度随之变化；
5. 有人认为某单元有错：提交竞争单元，以"取代"引用挑战它；
6. 应用通过 API 读取知识与可信度，或导出全部单元。

## 产品边界（不做什么）

- 不存储文件二进制（正文在仓库，链上只存哈希）；
- 不管理用户私钥；
- 不做私有知识库的检索与运行记录（那是 Knowledge）；
- 不裁判"真"与"新"：可信度来自核验记录与依据关系，不来自链的判断。
