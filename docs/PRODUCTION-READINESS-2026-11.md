## 4. 阻断项排序(主网)

1. **独立第三方安全审计**——最大、不可自我替代。治理(#10 攻击面 5「全新、未审计」)、桥
   (历史 bug 高发)、codec(最高危)尤需外部复核。
2. **经济参数校准**——需真实测试网多周运行 + 对抗建模反校,否则增发/罚没/质押激励可能被套利。
3. **规模化 + 对抗 + 分区/混沌测**——当前只有单元/集成测 + fuzz-lite/cargo-fuzz;无长跑、无网络
   分区下的安全/活性验证、无治理洪流压测。
4. **自动 liveness 问责缺位**——许可制可接受(运营手动处置);开放网络下宕机/审查零成本。

## 7. 附录:外部审计作为「已接受风险」后的部署判断(应运营方要求)

运营方要求**暂时搁置**「无独立第三方审计」这一阻断(作为**自觉接受的风险**),据此重判。

**关键认识:搁置审计 ≠ 清除其余阻断。** 审计是「人工复核」类保证,可由运营方签字接受风险而暂缓;
但**经济校准**与**规模化/分区/混沌测试**是**经验性**缺口——无法靠「决定」消除,只能靠真实运行数据
补上。因此:

| 形态 | 搁置审计后的判断 | 仍需满足 |
|---|---|---|
| 受控 / 许可制生产(已知运营方、价值有界) | ✅ **可带风险部署** | §11 工程项(已备)+ 保守经济初值(用 `sim/CALIBRATION.md` 推荐,即便未完全校准)+ ≥4 可信验证人 + 监控告警开 + 远程签名器托管密钥 + 运营方书面接受 §10 边界(无自动 jailing / 无滚动升级 / 经济未校准) |
| 公开激励测试网 | ⚠️ 谨慎 | 上面 + 先在测试网跑 **经济校准**(本就应在测试网做,审计无关)+ 治理/桥对抗观察 |
| 高价值 / 开放去中心化主网 | ❌ **仍不建议** | 即便接受审计风险,**经济未校准**(可被套利)与**无规模化/混沌测**(安全/活性未经压)两项**经验性**阻断未除。这两项不是「决定」能豁免的。 |

**结论(搁置审计后)**:
- **可以**上**受控/许可制生产**(运营方带风险接受),工程与运维件齐备。
- **仍不可**上**高价值/开放主网**——阻断从「3 项」减为「2 项」(经济校准、规模化测试),但这两项必须
  用真实运行数据补齐,无法仅凭风险接受豁免。

**建议的最小落地路径(受控生产)**:① 用 `sim/` 保守推荐值定 genesis;② `testnet/` 起 ≥4 节点
跑数日观察增发/罚没/供应守恒与 `docs/ops/` 告警;③ 验证人用远程签名器 + 加密 keystore;④ 运营方
签署《已知边界接受书》(§10 + 本附录);⑤ 上线后持续用这段真实数据反校经济参数,经链上治理微调。
