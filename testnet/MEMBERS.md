# 加入知行图测试网 · 成员指南

> 这份说明可以直接转发给第一批成员。

## 你需要做的只有一件事:在夜莺钱包里准备好知行图密钥,把公钥发给组织者

你的密钥就是你在链上的身份。**只有你自己持有它**,组织者和其他任何人都拿不到。
密钥由[夜莺钱包](https://wallet.yeying.pub/)保管:网页不持有私钥,每次要签名,钱包都会弹窗显示
"要签的是什么"(例如"核验单元 #8 的 v2:通过"),你确认后才签。

> 早先的做法(在网页「我的身份」里生成身份、密钥存在浏览器里)**已经下线**。已经是成员的,
> 见下面"已经是成员:把密钥移进钱包"——你的链上账户不会变。

### 第一步:把知行图账户导入钱包(只需一次)

安装夜莺钱包,打开钱包 → **账户管理 → 右上角「⋯」→ 导入钱包**:

| 你手上有什么 | 选哪个页签 | 说明 |
|---|---|---|
| 24 个词的助记词 | **「助记词 / 私钥」→「助记词」** | 网络选「知行图」,输入那 24 个词;有 BIP-39 附加口令的,填到下面的「助记词口令」 |
| `node keygen` 生成的加密文件(`.json`,`--encrypt` 生成) | **「备份文件」** | 选择这个文件,钱包自动认出是知行图密钥文件,再填**文件口令** |
| `node keygen` 生成的明文种子文件 | **「备份文件」** | 选择这个文件;不用口令 |
| 64 位十六进制种子(文本) | **「助记词 / 私钥」→「私钥」** | 网络选「知行图」,直接粘贴那 64 位十六进制 |

最后设置(或输入)钱包密码,点导入。派生规则与 `node keygen` 完全相同:**同一组助记词 / 同一个文件,
导入后就是同一个链上账户**。导入后它就出现在账户列表里,账户地址就是你的**公钥**(64 位十六进制)。

还没有任何密钥(新成员)?先用命令行生成(见下面"用命令行生成"),**把 24 个词按顺序抄在纸上,妥善保管;
不要拍照、不要截图、不要发给任何人**,再按上表导入。

### 第二步:在网页上登录

打开 https://blockchain.yeying.pub ,右上角点 **「用夜莺钱包登录」**,在钱包弹窗里确认"连接知行图"。
「我的身份」页会显示你的公钥和状态;还不是成员的话,把公钥发给组织者。

**看不到按钮?** 打开「我的身份」页看提示:
- "✗ 没有检测到夜莺钱包":钱包插件没装、没启用,或没在这个站点生效。装好/启用后**刷新页面**;
- 点了之后提示"钱包里还没有知行图账户":先做上面的第一步;
- 提示"钱包还不支持知行图":把钱包升级到最新版本。

### 已经是成员:把密钥移进钱包

你的链上账户由公钥决定,**导入同一把密钥就是同一个账户**,核验记录、邀请关系都不变。

1. 找出你当初生成身份时留下的东西:**24 个词的助记词**,或 `node keygen` 写的**密钥文件**;
2. 在钱包「账户管理 → 导入钱包 → 知行图」里按上表导入,**核对账户地址与你原来的公钥一致**
   (组织者那里有成员名单里的公钥,可以对一下);
3. 打开网页用钱包登录,「我的身份」应显示 **"账户 N · 已过见习期"**(第一批成员的编号就是名单里的顺序);
4. 如果你以前在网页里生成过身份,页面会提示"这个浏览器里还留着旧版网页自己保存的密钥"——
   确认钱包里导入的是同一把后,点 **「清除本机旧密钥」**。

**找不到助记词,也没有密钥文件?** 那把密钥就找不回来了(谁也帮不了你恢复,这正是"只有你自己持有"的代价)。
这时用命令行生成一把新密钥、导入钱包,把新公钥发给组织者,由一位老成员**重新邀请**你;新账户需要经过见习期。

要注意:
- 钱包里可以导入多个知行图账户;网页登录和签名用的是钱包里**当前选中**的那个。换了账户要在网页上重新登录。
- 知行图账户不随钱包的备份同步走:助记词或密钥文件要自己保管好。
- 钱包「网站管理」里能看到哪些网站连接过你的知行图账户,可以随时撤销。

### 用命令行生成(可选)

```sh
cd node && cargo build --release      # 生成 node/target/release/node
node keygen --new-mnemonic --encrypt --out zhixing-member.json
```

程序会让你设置一个密码,然后打印公钥(发给组织者)、密钥文件(自己保存)和助记词(抄在纸上)。
然后在钱包里「导入密钥文件」(选 `zhixing-member.json`,输入它的口令)或「用助记词导入」即可。

### 把这三项发给组织者

```
称呼:张三
方向:fitness(运动健身)或 llm(大模型应用开发)
公钥:03d330c69dabf7000b34af803bd9da850da0ac808d80d10e2952e84e5b74e35e
```

**绝不要发送**:助记词、口令、密钥文件。组织者不会、也不需要向你要这些。

## 测试网开启以后

### 你能做什么

- **写知识**:创建知识单元、为已有单元发布新版本(任何成员都可以修订别人的单元,你会被记录为修订者);
- **核验**:对别人发布的版本给出"通过"或"需修改"的结论。你不能核验自己发布的版本;
- **邀请**:邀请新成员加入。新成员需要经过 **7 天见习期**,期间可以写知识,但核验不计入可信度、也不能邀请别人;
  每位成员**每天最多邀请一人**。第一批成员不需要见习期。

### 在浏览器里核验(推荐)

1. 组织者会私下发给你一个**写入令牌**(它只用来防止刷写入,不代表你的身份;你的身份由你的密钥签名证明)。
   在「我的身份」里粘贴并保存;
2. 打开要核验的单元(例如组织者发来的链接 `https://blockchain.yeying.pub/#unit/3`),读完正文;
3. 页面底部的 **「核验」** 区会列出该单元的"核验要点"。逐条确认、全部勾选后才能点 **「通过」**;
   发现问题就点 **「需修改」**;
4. 点了之后钱包会弹窗显示要签的内容(例如"核验单元 #3 的 v1:通过"),确认后才签。私钥一直在钱包里。
   登录状态只保存在当前页面,刷新后点一下「用夜莺钱包登录」即可。

**大模型应用开发方向的核验人**:请先读 [核验人上手指南](REVIEWER-GUIDE-LLM.md)。这个领域目前还没有一个
单元被核验过;从单元 #8(词元)开始,一次核验就能抬高 6 个下游单元的可信度上限。

过了见习期的成员还可以在「我的身份」里**邀请新成员**:请对方生成密钥、在钱包「账户管理 → 导入钱包 → 知行图」里导入,把公钥(账户地址)发给你。

### 在浏览器里写知识

- **写新单元**:Knowledge 页顶部点 **「写新单元」**。左边写正文(Markdown,已预填模板),右边实时预览;
  选择领域、来源(如实标注人工撰写或模型生成),在"引用"栏输入单元编号添加**依据**或**参见**
  (自动指向被引用单元的当前版本)。点 **「创建单元」** 后,浏览器会先把正文上传到正文仓库,再请钱包签名提交;
- **修订**:任何单元页上点 **「修订(发布新版本)」**,正文与引用会预填为当前版本,改完发布即可。
  任何成员都可以修订别人的单元,你会被记录为这个版本的发布者;**新版本需要重新核验**,之前的核验只对旧版本有效;
- 正文末尾请写 **「核验要点」**(编号列表):核验人在浏览器里必须逐条勾选后才能给"通过"。

批量导入一整个目录的单元文件,仍然用下面的 `tools/kimport.py` 更方便。

### 用命令行提交

提交接口是 `https://blockchain.yeying.pub/rpc/knowledge`,同样需要写入令牌。
所有操作都用你的密钥文件在**你自己的电脑上**签名,然后提交:

```sh
export ZHIXING_KEYSTORE_PASSWORD='你的密码'     # 或者不设置,运行时会提示输入
export ZHIXING_RPC_TOKEN='组织者发给你的写入令牌'
RPC=https://blockchain.yeying.pub/rpc

# 查你的当前序号(nonce):
curl -s $RPC/account/你的编号

# 例:核验 5 号单元的第 1 版,结论"通过"
node encode-knowledge-op --key-file zhixing-member.json --out op.bin \
  --actor 你的编号 --nonce 你的序号 --action verify --unit 5 --version 1 --verdict pass
curl -s -X POST -H "Authorization: Bearer $ZHIXING_RPC_TOKEN" \
  -H 'Content-Type: application/octet-stream' --data-binary @op.bin $RPC/knowledge
```

每提交一条,序号加一;等它入块(约 1 秒)再签下一条。

### 正文放在哪里

链上只记录正文的 **SHA-256 哈希**;正文本身放在测试网的**正文仓库** `https://blockchain.yeying.pub/bodies/<哈希>`。
浏览器打开单元时会取回正文、在你的浏览器里重新计算哈希,一致才显示("✓ 正文与链上哈希一致")。
所以**创建单元或发布新版本时,要先上传正文**(仓库只接受哈希相符的内容,别人无法替换你的正文):

```sh
H=$(shasum -a 256 单元文件.md | cut -c1-64)   # 与 node hash-content --file 单元文件.md 相同
curl -s -X PUT -H "Authorization: Bearer $ZHIXING_RPC_TOKEN" --data-binary @单元文件.md \
  https://blockchain.yeying.pub/bodies/$H
```

批量导入一个目录下的单元文件,用 `tools/kimport.py`,它会自动上传正文、取序号、等待入块:

```sh
python3 tools/kimport.py --rpc $RPC --bodies https://blockchain.yeying.pub/bodies \
  --key 你的编号=zhixing-member.json --dir 单元目录 --domain 领域编号   # 1 大模型应用开发,2 运动健身
```

### 怎么阅读与核验

在浏览器的 Knowledge 页点开单元即可阅读正文;每个单元有固定链接,例如
`https://blockchain.yeying.pub/#unit/3`,可以直接发给别人请他核验。

### 被依据的单元更新了怎么办

"依据"锁定被引用单元的某个版本。它发布新版本后,浏览器会在下游单元上显示"引用已过时",
下游的有效可信度也会被旧版本卡住。确认新版本没有改变你的单元赖以成立的内容后,发布一个跟进版本:

```sh
python3 tools/kfollow.py --rpc $RPC                       # 列出所有依据已过时的单元
python3 tools/kfollow.py --rpc $RPC --unit 6              # 查看要做的改动(不提交)
python3 tools/kfollow.py --rpc $RPC --unit 6 --key 你的编号=zhixing-member.json --yes
```

任何成员都可以跟进任何单元(你会被记录为该版本的发布者)。如果新版本确实影响了你的单元,
应该修改正文后发布新版本,而不是只跟进版本号。

### 核验时请注意

- 先读单元末尾的"核验要点",逐条确认;
- 你只对**核验当时能知道的东西**负责。如果后来出现了新证据推翻了它,那是"诚实的错",不会受罚;
- 遇到真正有争议的问题(比如学界尚无定论),不要强行判对错,可以提交一个观点不同的新单元,两者并存。

也**不承诺**任何兑换关系。
